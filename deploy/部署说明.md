# 发现／加密中转服务

本项目尚未部署任何公网服务。客户端安装包不会自动拥有一个可用的公网地址。
只需部署一个轻量服务：用于设备发现、WebRTC 信令、无法直连时的密文转发。
三台客户端不需要各自开公网端口，也不要求某台客户端持续开机。客户端均需使用 0.1.1 并分别添加同一账号；旧版通信房间不兼容。

## 服务不保存哪些数据

- 不接收 Codex OAuth Token、密码、邮件地址或原始对话。
- 不保存使用量账本；账本保存在各客户端 SQLite 中。
- 中转能看到连接 IP、不透明房间标识、消息长度、时序和设备随机 ID。
- 消息内容（包括 WebRTC SDP）由客户端 AES-GCM 加密。
- 服务离线时已有直连可继续；新设备发现、重新配对和中转连接暂时不可用。

## Linux / Docker 部署

准备一台公网主机和指向它的域名，将完整源码放在服务器目录。
需要允许 TCP 80、443 入站，内部 48733 不对公网暴露。

```bash
cd deploy
cp .env.example .env
# 将 CQG_DOMAIN 改为真实域名，CQG_RELAY_TOKEN 改为足够长的随机值。
# 如本机有 Python，可用以下命令生成随机值：
python -c "import secrets; print(secrets.token_urlsafe(32))"
docker compose up -d --build
docker compose logs --tail=30
```

Caddy 为该域名管理 HTTPS 证书。需要域名解析和端口可达才能成功签发。
客户端填写 `wss://你的域名` 和同一个 `CQG_RELAY_TOKEN`，保存后生成匹配码。
**不要使用示例域名或示例密钥作为真实部署配置。**

Docker 配置已提供，但本次没有真实公网主机可部署，因此该部署路线未做公网验收。

## Windows 服务端

附带的 `CodexQuotaRelay.exe` 是控制台程序：

```powershell
.\CodexQuotaRelay.exe --generate-token
$env:CQG_RELAY_TOKEN = '换成生成的随机值'
.\CodexQuotaRelay.exe --host 127.0.0.1 --port 48733
```

再使用可信 TLS 反向代理对外提供 WSS。默认只监听回环，避免把明文 WebSocket 暴露公网。
客户端严格验证系统信任的 TLS 证书；生产模式不接受 `ws://`。
未附带 Windows 服务注册或自动开机脚本；先验证服务和域名可达，再按主机运维方式托管。

## 排查

1. 服务访问密钥相同但设备互相看不到：检查匹配码的设备组是否相同、Codex 账号是否相同。
2. 能中转但无法直连：NAT、UDP、VPN/代理策略可能阻止 ICE；保留中转即可，不要强行关闭原代理。
3. 开启“仅使用加密中转”可单独验证 WebSocket 路径。
4. 客户端系统时间误差超过 60–90 秒会被拒绝同步，请同步 Windows 时间。
5. 匹配码泄露：创建新的设备组/新配置，并重新配对全部可信设备；旧组秘密不能靠删除一个本地条目撤销。
