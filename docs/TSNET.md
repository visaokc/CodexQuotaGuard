# 内嵌 Tailscale 连接设计（0.3.0 本地候选）

## 架构

Python Engine / Journal → AES-GCM 消息 → 私有本机 IPC → Go tsnet → 对端 tsnet → 同账号 Cipher → Journal。

- 单个主 EXE 内含 `cqg-tsnet.exe`，这是本项目编译的 tsnet 宿主，不是官方 CLI 安装器。不安装系统服务、虚拟网卡或全局路由，不调用 Funnel，不修改光猫、系统 Tailscale 或其他应用配置。
- 生产入口只加载 `quota_guard.transport`，不加载旧 WebRTC/Syncthing 传输。旧实现保留在源码用于历史回归，不进入主包通信路径；轻量包不含 Syncthing、aiortc、PyAV/FFmpeg。
- tsnet 使用官方默认控制服务和 DERP；首次在浏览器授权同一 tailnet。用户若自行配置 Peer Relay，UI 如实显示 Peer Relay，不冒充官方 DERP。
- Tailscale 登记与条款由用户完成。Codex 账号登录和 Tailscale 网络身份是两套独立身份；加入 tailnet 不代表通过应用组密钥或同 Codex 账号校验。

## 生命周期与安全

- 仅监测已添加的当前订阅账号时启动。账号/API 切换由 Engine 关闭通信层；不沿用另一账号的在线状态或回执。
- tsnet 身份持久保存在用户数据目录 `tailscale/`。不要删除、分享或把它打进分发包；它不放在 EXE 解压目录。当前使用 tsnet 默认文件状态存储，由 Windows 用户目录权限保护，并非应用额外 DPAPI 加密的状态库。
- 隐藏的子进程绑定 Windows Job。stdin 关闭也触发退出，避免主程序退出后残留节点。
- 控制端口仅监听 `127.0.0.1` 随机端口；每次随机 Bearer capability 通过继承管道传递，不进入命令行、匹配码或日志。浏览器不能匿名读取授权链接或发送同步。
- tailnet 内仅监听专用 TCP 24817。发送目标必须是 tsnet 当前 peer map 的精确节点 IP，不允许通过同步接口访问任意公网、LAN、子网路由或重定向地址。
- 消息仍通过既有组密钥和账号派生 AES-GCM 密钥认证；保留时间窗口与重放拒绝。消息、接收队列和待发槽位有上限。不会传输 Codex 凭据、对话、原始日志或数据库文件。
- 禁止继承外部 TS_AUTHKEY、TS_CONTROL_URL 等配置。关闭 tsnet 自动日志上传；官方控制服务仍需要正常节点元数据。

## 配对与迁移

- CQG4 含应用设备 ID、组密钥和稳定 tailnet IP；地址校验只接受 Tailscale 地址范围。校验和仅检测复制损坏，不是身份认证；匹配码本身是组访问凭证。
- 发起方升级后保留原 `group_secret`、设备 ID 和账本，授权后刷新 CQG4；另一台升级授权后粘贴。接收方不复制发送方的本机设备 ID。
- 接收方向发起地址发送加密 hello，发起方验证后从 tailnet 连接学习回程地址，按组持久化；双方无需交换两次地址。对端重新注册导致地址变化时重新交换匹配码。
- CQG1/CQG2 旧码仍可由纯解析器识别，但新版 UI 拒绝用于连接，明确要求原组发起方刷新。旧账本不删除，不创建伪造的合并归属。
- 未收到 ACK 的历史由 Journal 版本向量重新生成；发送失败不当成账本确认。不再经过文件邮箱扫描周期。

## UI 证据

- 节点启动、待登录、待管理员批准、节点就绪，与对端已认证、已收到用量同步分别显示。
- 在线依据近期通过应用认证的消息，不用 Tailscale 控制面 `Online` 替代。
- 每个在线对端约 15 秒做一次 Disco 路径探测，区分 Endpoint 直连、DERPRegionID 中转和 PeerRelay。35 秒未更新或探测失败显示“路径待确认”，不凭 Relay 归属区域推断在走中转。
- 路径是近期探测结果，不承诺逐包走同一路径。数据新鲜度由独立同步回执呈现。

## 验收边界

本地测试覆盖协议、账号隔离、持久化、队列、IPC、Windows 子进程、授权 URL 获取和实际 GUI 控件。UI 的直连/DERP 截图使用明确演示状态。

必须由用户在两台设备授权后，再验收真实同步、重启补传、网络切换与 direct/DERP 路径。未完成前不声称异地连通、特定延迟或全部历史已收敛。不会自动安装独立 Tailscale 或修改系统网络设置。

## 组内移除设备

设备总览选择其他设备后点击“从组中移除选中设备”，必须二次确认，默认取消。
成员状态按组持久化，通过已认证的 hello 传播版本化的移除／加入记录，离线成员恢复连接后收敛；同版本冲突优先移除。
已移除设备从设备总览删除对应行，也不计入当前已配对设备 Token 合计；底层历史账本保留。不再发送或接收账本数据，仅保留移除标记传播，以通知离线成员。
进程重启和旧心跳不能清除移除状态。被移除设备必须主动重新输入匹配码；收到匹配对象的成员状态后创建更新版本的加入记录，并将此次匹配请求标记为已使用。后续再次移除不会因旧匹配请求或重启自动恢复。历史账本和应用设备 ID 不改变。
所有成员应升级到支持此协议的版本。这是合作客户端的组成员管理，不是 Tailscale ACL 撤权；共享组密钥的旧版或篡改客户端不具备密码学身份撤销保证。它不会删除 Tailscale 控制台中的机器，也不擦除对端已持有的历史数据。
