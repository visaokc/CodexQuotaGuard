# WebView interface contract

The new desktop UI uses local Vue 3 assets in WebView2; the existing Python Engine, journals, billing and sync implementations remain authoritative.

Bridge object: `window.pywebview.api`.

- `snapshot()` -> `{version, view, settings, accounts, pairing, update, notices}`. `view` has the existing Engine.snapshot fields, including summary and analytics. Strip auth tokens, private group settings and arbitrary transport payloads. `settings` includes only device_id, name, quota_display, device_notes, device_colors, device_order, autostart, auto_update, auto_block, codex_home, interval, program_paths, force_relay, quota. `accounts` is the allowed tracked account metadata. `pairing` is safe progress only. `update` is safe status/version only. Never transmit secrets in periodic snapshots.
- `command(action, payload={})` -> `{ok:true,data:...}` or `{ok:false,error:string}`. Supported actions: refresh, account_scan, account_add, account_remove, account_history, cap_save, limit_toggle, restore, note_save, color_save, device_order_save, device_remove, settings_save, programs_discover, pair_generate, pair_join, tailscale_login, tailscale_switch, connection_save, update_check, update_install, diagnostics.
- Common payload keys: account (account id), device (device id), cap (percentage), text (note), color (allowed hex preset), code (pairing code), enabled (boolean), settings (allowlisted settings map).
- Pairing, enrollment and update actions must implement equivalent existing gui.py behavior, validate input, and preserve explicit UI confirmations for destructive/interrupting operations. The front end uses custom modals, never native JS alert/confirm.
- Host provides `window_action(action)` for minimize, close (hide to tray), quit, drag, maximize, shown, browse_program, export_diagnostics. Backend controller may expose a private callback set by the host. Use the controller contract described by the implementing agent; coordinate exact callback interface before integration.
- `close()` in the Python controller is private host lifecycle, not a public JS method; use `_close()` or a non-exposed runtime owner.

Charts: raw Token only; pie defaults to current cycle and all-model values come from the same summary device rows. Preserve hour/day/week/month and explicitly named history total. Whole-account pie device comparison stays visible when trend filters an individual user. Filter removed devices everywhere. Pie center empty; only on hover show the hovered device Token in card bottom-left, small text. Pie legend has spaced names and Token values without percentage. Device estimated quota uses weighted allocation and selected personal/account denominator.

UI: 750x570 compact dark shell, top navigation, no native title bar, native OS dragging, main no scrollbar, three cards including confirmed sync receipt time; retain all account/sync/settings/help actions. Blue usage badge, 8 pleasant color presets, persistent device selection, real grouped data. Model and user filters adjacent; line/bar toggle on right near period control. CSS transitions and rAF for charts; do not recreate DOM trees on snapshot polling. No online CDN, no fake production data. Offline preview data must be clearly isolated test fixtures.
