# 0.4.0 WebView2 试用版性能实测

2026-09-10，本机 RTX 3080 Ti，750 × 570 窗口。新旧版使用同一份冻结账本数值，三轮取中位数；不启动 Engine、不连接远端、不修改原账本。新版已确认 WebView2 使用 ANGLE / Direct3D11。

| 指标 | 上一版 Tk 试用版 | 新版 WebView2 | 变化 |
|---|---:|---:|---:|
| 折线悬停 3 秒，进程 CPU 时间 | 1375 ms | 3250 ms | 增加 136.4% |
| 柱状悬停 3 秒，进程 CPU 时间 | 1281 ms | 2547 ms | 增加 98.8% |
| 空闲私有内存 | 90.9 MiB | 291.4 MiB | 增加 220.5% |
| 空闲 2 秒，进程 CPU 时间 | 15.625 ms | 15.625 ms | 未测出差异 |
| 源码启动到首屏布局 | 2.936 秒 | 5.104 秒 | 增加 73.9% |

新版统计包含 Python 和所有 WebView2 子进程。CPU 时间可以跨多个线程累加，不是整机 CPU 占用百分比。新版每轮使用新的浏览器配置目录，启动数据也不是最终 EXE 的日常启动速度。

新版动画时钟间隔中位 6.9 ms，95% 的间隔不超过约 7.2 ms。上一版折线重绘完成间隔 p95 为 27.63 ms，但两者测量位置不同，不能据此声称 FPS 提升百分比；此次没有测实际屏幕呈现帧率，也没有操纵真实鼠标来测原生拖动。

已经验证的变化：

- 拖动由 Windows 原生移动循环处理，移除 Python 逐点移动队列。
- SVG 与浏览器渲染替代 Pillow 逐帧生成图片；曲线悬停沿曲线连续移动。
- 连续 20 次相同快照更新，SVG 变更次数为 0，下拉框和设备选中状态保留。
- 窗口启动、最小化、任务栏恢复、隐藏到托盘、托盘恢复的透明度过渡通过真实 Windows 宿主探针。
- 同周期、全部模型的饼图与设备列表使用同一份 Token 数据，历史累计明确分开。

结论：这次解决的是界面渲染与交互方式，实测资源开销增加，不能宣传为全面降耗，也暂不提供未经测量的“流畅度优化率”。屏幕上的拖动手感由本次试用验收。完整测试方法见 [performance-baseline.md](performance-baseline.md)。
