## 77% 与 92% 不能只按 Token 比例比较

个人百分比来自账号官方额度的分摊，个人份额 50% 时，账号百分点乘以 2。历史记录补齐会改变分摊权重；另一个设备的对应分摊随之改变，账号官方已用仍是官方的值。

此前个人列表使用整个周期的权重，历史截图中的图表使用按官方增量所在时段分摊的权重，存在两处不同的数值。当前版本的图表、个人列表、用户汇总已统一使用后者，本次跟进不再改变该分摊算法。

核查时本机已经官方增量校准的份额是 45.6394637388 个账号百分点，即个人模式 91.2789274777%。先前约 92% 还含了官方尚未跳动部分的实时预测。本次取消该预测，不通过删除真实日志或硬编码数值恢复 77%。

“推算本周期总量”仍是已有的容量推算功能，回补会改变其样本和结果；它不是官方宣布增加了 Token 额度。

## 最新计算规则

- 总 Token = 输入 + 输出。缓存已包含在输入中，推理已包含在输出中，均不能重复相加。
- 未命中输入 = 输入 − 缓存命中。缓存命中率 = 缓存命中 / 输入。
- Token、输入、输出、缓存数量实时累计日志实数。
- 额度只分摊官方已经确认的增量；官方未跳动时保持已有校准值，不预测下一段额度。尚无任何校准的时段显示“待更新”。
- 缓存额度是官方增量中按缓存用量权重分出的部分，不等于缓存命中率；个人模式只换算一次。
- 官方并未提供独立的每设备或每缓存扣费账单，个人和缓存百分比仍是对官方总额的分摊，不能称为官方个人实测。

## 补偿开关

跨周期补偿默认关闭，没有开关事实的旧账本也默认关闭。关闭时当前补偿为零，后续周期沿用原始份额，两人各 50%；历史事实保留，不删除原始使用量。本周期超额仍可显示 110% 或更高。

开关通过现有账号同步事实传播。开启时从本次开启所在周期恢复结算，不追补先前关闭期间已结束的周期。关闭再开启也不重新施加之前的补偿。自然重置、重置卡和官方临时重置仍遵守已建立的结算分类。双方需升级才能同样执行开关。
